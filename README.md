# Сканер MikroTik

Инструмент сетевого администратора для инвентаризации устройств MikroTik / RouterOS
в своей сети: сканирование подсетей, опрос устройств через RouterOS API или SSH,
выполнение команд на выбранных устройствах и сохранение текстовых бэкапов (`.rsc`).

> Работает только с устройствами, к которым у вас есть учётные данные и полномочия
> на управление. Перебора паролей и эксплойтов здесь нет — вход выполняется
> логином и паролем, которые вы вводите сами.

Весь интерфейс на русском; названия столбцов IP, Identity, RouterOS, License и
Winbox оставлены как есть.

## Установка и запуск

```bash
pip install -r requirements.txt     # нужен только для SSH (paramiko)
python3 mikrotik_scanner.py         # на Windows: python mikrotik_scanner.py
```

Нужен Python 3.8+ с `tkinter` (на Linux при необходимости `sudo apt install python3-tk`).
`paramiko` нужен только для типа команд SSH; он закреплён версией ниже 4, потому что
paramiko 4+ не умеет говорить со старыми RouterOS 6.x.

## Кнопки

| Кнопка | Что делает |
|---|---|
| **Скан** | Сканирует сеть из поля «Сеть» и **добавляет** найденные устройства к таблице (уже известные обновляет). Остальную таблицу не трогает и не опрашивает. Пример: в таблице `10.20.0.0/16`, а в подсети `10.20.76.112/28` что-то изменилось — введите её и нажмите «Скан». Известное устройство из этой подсети, которое перестало отвечать, краснеет. |
| **Новый скан** | То же, но сначала очищает таблицу и сбрасывает фильтры (спрашивает подтверждение). |
| **Пауза / Стоп** | Работают для любой операции. «Стоп» не запускает новые устройства, начатые доделываются. |
| **Обновить** | Заново опрашивает устройства, **показанные в таблице** (все, а при включённом фильтре — только отфильтрованные, например только с ошибками). Поле «Сеть» не используется. Одно устройство можно обновить значком ⟳ в его строке. |
| **Удалить** | Убирает отмеченные (видимые) строки из таблицы и сохранённого списка — после подтверждения. Сами устройства и файлы бэкапов не затрагиваются. |
| **Бэкап** | Сохраняет `/export` отмеченных роутеров в папку `Backups/` (имя `IP_Identity_ГГГГ-ММ-ДД.rsc`). |
| **Отправить** | Выполняет текст выбранной вкладки «Команда 1–10» на отмеченных устройствах. Если открыт лог — последней выбранной командной вкладки. |

Сеть можно задавать так: `192.168.0.0/24`, `10.0.0.10-20`, `192.168.0.5`, несколько
через пробел или запятую.

Скан и обновление используют выбранный «Тип команд». В режиме **SSH** опрос идёт
через порт из поля «SSH» (по умолчанию 22), API не требуется. Получаются Identity,
модель, RouterOS, лицензия, серийный номер и IP-адреса. Если при «Обновить» (или ⟳)
SSH не отвечает на адресе подключения, пробуется адрес с `bridge1` — так же, как при
бэкапе. Если устройство ответило, но данные прочитать не удалось, в ошибке показан
ответ устройства, а полный ответ записывается в лог.

В режиме **API/SSL** используется порт API-SSL (по умолчанию 8729). Если этот порт
закрыт, программа пробует обычный API на 8728. Роутеры старше RouterOS 6.43 (двухшаговый
вход) поддерживаются. Если соединение рвётся уже после входа, оно повторяется (**Повторы**).
Дубликаты (один роутер с несколькими адресами) сворачиваются в одну строку с адресом
на `bridge1`; устройства сопоставляются по серийному номеру.

### Тип команд

«Тип команд» определяет транспорт для **Скан**, **Новый скан**, **Обновить**
(включая обновление одной строки), **Отправить** и **Бэкап**. Команды **не
конвертируются** — текст уходит на роутер ровно так, как вы его ввели:

- **SSH** — как в терминале RouterOS (можно несколько строк): `/ip service set ssh port=61562`.
  Нужен `paramiko` и правильный порт в поле «SSH».
- **API/SSL** — каждая строка — одна команда в формате API, слова через пробел (слова с
  пробелами — в кавычках): `/ip/service/set =numbers=ssh =port=61562`, запрос —
  `?name=ssh`, параметры — `.proplist=name,port`. Если строка написана как терминальная
  команда, ничего не отправляется, и программа подсказывает, что такие команды
  выполняются в режиме SSH.

Бэкап по API работает так: `/export file=...`, чтение файла, удаление файла. На
RouterOS 7.13+ размер любой; на более старых API отдаёт только ~4 КБ, и для большого
конфига программа сама повторяет бэкап по SSH.

«Отправить» и «Бэкап» подключаются по тому адресу, который ответил при скане (в таблице
показан адрес с `bridge1`, он может быть недоступен с этого компьютера; в CSV это
столбец «IP подключения»). Одновременно обрабатывается до 10 устройств (и не больше
значения «Потоки»); при «Потоки» = 1 — по одному.

### Поля и вкладки команд

Все поля подключения расположены в одной строке (помещается в окно шириной 1280 px),
кнопки — под ними. Если окно уже, строка полей прокручивается горизонтально: колесом
мыши над ней или полосой прокрутки, а поле, в которое перешли клавишей Tab, само
прокручивается в видимую часть.

Для команд доступны 10 независимых вкладок «Команда 1» — «Команда 10».
При переключении текст сохраняется. «Вывод / Лог» — последняя вкладка справа;
после отправки она открывается автоматически, а в логе указано, какая вкладка ушла
на устройства («Команда 5»). Тексты всех 10 вкладок и выбранная вкладка сохраняются
**всегда** (файл `commands.json`, без пароля) — независимо от галочки «Запомнить
настройки», которая хранит логин и пароль. Команда из старого файла настроек
переносится в первую вкладку.

## Таблица

- **Столбцы**: IP, Identity, Модель (Board Name), RouterOS, License, Был в сети,
  Последний бэкап, Статус, Winbox, Заметка. Сортировка — по клику на заголовок.
  **Ширина столбцов запоминается** (файл `ui.json`); если столбцы не помещаются в окно,
  внизу появляется прокрутка.
- **Чекбокс** слева, рядом значок **⟳** (обновить это устройство). Они чуть крупнее
  текста (нарисованы картинками). Галочка в заголовке отмечает/снимает все
  **видимые** строки. **Shift+клик** отмечает диапазон между двумя кликами.
- **Правый клик**: «Копировать ячейку», «Копировать строку» (через табуляцию — вставляется
  в Excel по ячейкам), «Изменить заметку…».
- **Двойной клик по «Последний бэкап»** открывает самый свежий файл бэкапа устройства
  программой, назначенной в системе для `.rsc`.
- **Двойной клик по «Заметка»** — ввести комментарий к устройству. Заметка хранится вместе
  со списком, не теряется при обновлении и ищется поиском.
- **Winbox**: кнопка **▶ Winbox** в строке запускает `winbox.exe` из папки с программой
  (подойдёт любой `winbox*.exe`) с адресом, логином и паролем из верхней панели. Порт —
  поле «Winbox» (8291). Пароль в лог не пишется, но пока Winbox запущен, он виден в
  командной строке процесса.
- Над таблицей — счётчики: `Устройств: 12 (показано 5) · отмечено: 3 (ещё 2 скрыто) · с ошибками: 1`.
- Список устройств автоматически сохраняется в `devices.json` и загружается при
  запуске, поэтому большие сети не нужно сканировать заново.

### Фильтры, поиск и цвета

- **Поиск** (внизу слева) — это фильтр: пока строка не пуста, остаются только устройства,
  в которых встречается каждое введённое слово (любой столбец, включая «Заметку»;
  регистр не важен). «Очистить» или Esc возвращают все строки. Ищется то, что видно
  в таблице.
- **Модель** — кнопка открывает список моделей с количеством устройств; отметьте сколько
  угодно, остальные скрываются; «Показать все» сбрасывает выбор.
- **Бэкап: Старше 3 / 6 / 12 мес.** — только устройства с таким старым последним бэкапом
  (устройства вообще без бэкапов сюда не входят — для них есть отдельная галочка).
  **Только с ошибками** и **Только без бэкапов** — галочки. Все фильтры сочетаются (по «И»).
- **Цвета строк**: жёлтая / оранжевая / красная — последний бэкап старше 3 / 6 / 12 месяцев
  (легенда над таблицей); бледно-розовая с тёмно-красным текстом — последняя операция с
  устройством закончилась ошибкой (причина — в столбце «Статус»); ошибка важнее цвета
  возраста. Следующая удачная операция снимает красный цвет.
- Отметки скрытых фильтром строк **сохраняются**, но **Бэкап, Отправить, Удалить и
  Экспорт работают только с видимыми строками**.

### Экспорт и импорт

CSV с разделителем `;` и русскими заголовками (открывается в Excel). Экспорт сохраняет
показанные строки. Импорт понимает и русские, и старые английские заголовки, и файлы
с запятыми.

## Прогресс

Под полосой прогресса — что выполняется, сколько сделано из скольких, сколько прошло и
сколько примерно осталось (после первых нескольких устройств; время на паузе не
считается), сколько успешно и сколько с ошибками. Одновременно выполняется одна
операция.

## Если SSH не подключается к отдельным устройствам

Подключение по SSH повторяется автоматически (**Повторы**), а в ошибке написано, что
сделало само устройство, и добавлена диагностика:

- `Error reading SSH protocol banner` — устройство приняло соединение и сразу закрыло его
  или промолчало, не прислав приветствие SSH. Причины: перегруженный роутер, лимит
  подключений или правило фаервола (connection-limit, защита от перебора, tarpit), либо
  на порту не SSH.
- `Negotiation failed` — устройство само разорвало сессию во время обмена ключами; в
  сообщении показано его `Disconnect (code N): причина`.
- `диагностика: ...` — после неудачи программа коротко заглядывает на порт и пишет, что
  там происходит (нет приветствия / закрыто сразу / не SSH / нет общих алгоритмов, с
  перечнем алгоритмов устройства).

## Логи

Каждый запуск пишет подробный лог в `logs/scanner-ГГГГММДД-ЧЧММСС.log` (версии Python и
OpenSSL, что пробовалось по каждому адресу, полный текст ошибок). Кнопка **Сохранить лог**
копирует его в выбранное место.

## API-SSL без сертификата

Если на роутере для api-ssl не назначен сертификат, RouterOS использует анонимные шифры;
многие клиенты их отклоняют (`SSLV3_ALERT_HANDSHAKE_FAILURE`). Программа явно их разрешает.
Для строгого TLS назначьте api-ssl сертификат в `/certificate`.

## Структура и тесты

| Файл | Назначение |
|---|---|
| `mikrotik_scanner.py` | Окно (Tkinter): таблица, фильтры, операции, импорт/экспорт |
| `core.py` | Логика без окна: опрос, дубликаты, сеть, бэкапы, возраст бэкапа, тексты прогресса |
| `routeros_api.py` | Клиент RouterOS API (plain + TLS), без зависимостей |
| `ssh_client.py` | SSH-инвентаризация, команды и `/export`, повторы, диагностика (paramiko) |
| `icons.py` | Значки чекбокса и ⟳ (картинки) |
| `mock_router.py` | Поддельный роутер для проверки без железа |
| `tests/` | Тесты; запуск: `python3 run_tests.py` (тесты окна пропускаются без tkinter/экрана) |
