# MikroTik Scanner

Инструмент сетевого администратора для инвентаризации устройств MikroTik / RouterOS
в своей сети: сканирование подсети, опрос устройств по официальному RouterOS API
(API-SSL, запасной вариант — обычный API), выполнение команд на выбранных устройствах и
сохранение текстовых бэкапов (`.rsc`).

> Работает только с устройствами, к которым у вас есть учётные данные и полномочия
> на управление. Это административный инструмент, а не средство несанкционированного
> доступа: перебора паролей и эксплойтов здесь нет — аутентификация выполняется
> логином/паролем, которые вы вводите сами.

## Возможности

- Скан подсети (CIDR `192.168.0.0/24`, диапазон `10.0.0.10-20`, отдельные IP, списки).
- Многопоточный опрос (**Threads**), настраиваемые **Timeout** (сек) и
  **Retries** (повторы). Некоторые роутеры перемежающе рвут TLS-сессию сразу
  после логина (`SSLEOFError`) — программа автоматически переподключается тем
  же транспортом (API-SSL) до `Retries` раз, а не считает устройство мёртвым.
  В plain API (8728) уходит только если порт API-SSL реально закрыт (refused),
  а не при обрыве уже установленной сессии.
- Сбор полей: **IP, Identity, Board Name, RouterOS, License, Last seen, Status**.
- Дедупликация роутеров с несколькими адресами (резервные каналы): в таблице
  остаётся одна строка — адрес на `bridge1`, первый по порядку. Совпадение
  устройств определяется по серийному номеру (`/system routerboard`), с запасным
  вариантом по `software-id`.
- Кнопки **New Scan / Pause / Stop**, **Update** (пересканировать известные
  устройства и остальные IP подсети), **Backup**.
- **Скан** всегда идёт через RouterOS API (API-SSL).
- **Command Type**: `API/SSL` или `SSH` — как отправлять команды (**SEND**) и
  делать **Backup**. Для SSH укажи порт в поле **SSH** и установи `paramiko`.
- **Send** — выполнить многострочную команду на отмеченных устройствах.
- Таблица с чек-боксами (выбор всех — по заголовку), сортировка по столбцам,
  поиск (**Find**), **Import/Export** в CSV.
- Галочка **Save** — сохранить введённые параметры (в `settings.json` рядом с
  программой) для повторного использования после перезапуска.

## Установка

```bash
python3 -m venv .venv && source .venv/bin/activate   # по желанию
python3 mikrotik_scanner.py
```

Требуется Python 3.8+ с `tkinter` (в некоторых дистрибутивах ставится отдельно,
например `sudo apt install python3-tk`). Для Command Type = SSH нужен `paramiko`:
`pip install -r requirements.txt`.

## Порты

- **API-SSL**: `8729` (TLS) — включается на роутере (`/ip service`), рекомендуется.
- Если порт API-SSL закрыт, программа сама пробует обычный API на `8728`.

## Бэкапы

Кнопка **Backup** сохраняет `/export` отмеченных роутеров в папку `Backups/`
рядом с программой (создаётся автоматически), имя: `IP_Identity_YYYY-MM-DD.rsc`.
Способ зависит от **Command Type**:

- **SSH** — выполняет `/export`, размер конфига не ограничен.
- **API/SSL** — выполняет `/export file=...`, читает файл и удаляет его с роутера.
  На RouterOS 7.13+ размер не ограничен. На более старых версиях API отдаёт только
  ~4 КБ: если конфиг больше, будет понятная ошибка (переключись на SSH).

Send и Backup подключаются к роутеру по тому адресу, который ответил при скане.
Адрес с bridge1 в таблице может быть недоступен с этого компьютера.
В CSV он сохраняется в колонке `Mgmt IP`.

## Формат команд

Команды пишутся в CLI-стиле, по одной на строку. В режиме `API/SSL` программа сама
переводит их в API-запросы, в режиме `SSH` текст выполняется как в консоли RouterOS:

```
/system identity print
/system identity set name=core-rtr
/interface print ?disabled=yes
```

## Что нового

- **Копирование/вставка** во всех полях и в логе (в т.ч. на русской раскладке:
  Ctrl+C/V/X/A по коду клавиши), плюс правый клик → меню.
- **Кэш результатов.** После скана таблица сохраняется в `devices.json` рядом с
  программой и подгружается при следующем запуске — не нужно пересканировать
  большие сети заново. Обновить данные — кнопкой **Update** или значком **⟳**.
- **Кнопка ⟳ в строке** (рядом с чек-боксом) — подключиться к одному роутеру и
  обновить только его.
- **New Scan** предупреждает, что таблица будет очищена; для дозаписи/обновления —
  **Update**.
- **Экспорт CSV** — разделитель `;` (и корректно открывается в Excel с рус.
  локалью). Колонка **Mgmt IP** — это адрес, по которому программа реально
  достучалась до роутера при скане (в колонке IP показан адрес с bridge1, он
  может быть недоступен с вашего компьютера). По Mgmt IP идут Send и Backup, и
  благодаря ему импортированный список тоже можно опрашивать.

## Логи (для отладки)

Каждый запуск пишет подробный лог в папку `logs/` рядом с программой
(`logs/scanner-ГГГГММДД-ЧЧММСС.log`): версия Python/OpenSSL, что пробовалось
по каждому IP, какой порт/транспорт, полный текст ошибок TLS/логина. Внизу окна
кнопка **Save Log** — сохранить текущий лог в отдельный файл, чтобы приложить
к репорту.

## Если устройство рвёт сессию сразу после логина (`SSLEOFError`)

Некоторые сборки RouterOS стабильно роняют api-ssl сессию сразу после логина,
если согласован **GCM-шифр**. Программа это ловит: если после логина сессия
рвётся, она автоматически переподключается, форсируя **CBC-шифр** (TLS 1.2).
В логе это видно как `retrying with cipher profile 'CBC'`. Так добираются
устройства, которые иначе не находились.

## Про API-SSL и «SSLV3_ALERT_HANDSHAKE_FAILURE»

Если на роутере в api-ssl не импортирован сертификат, RouterOS использует
анонимные шифры (ADH/AECDH). Многие клиенты их отклоняют — отсюда ошибка
рукопожатия. Программа явно разрешает эти шифры и понижает уровень
безопасности TLS, поэтому подключается и к таким роутерам. Если хочешь строгий
TLS — импортируй на роутере сертификат в `/certificate` и назначь его api-ssl.
